# Phase 4 data contract (schema 1)

V6 only. Generated by `scripts/gen_items.py`; V5 inputs stay unchanged. Consumers
must reject unknown schema, duplicate identities, missing references, unsupported
capabilities and hash mismatch. No TOML floats. All decimals are exact strings
accepted by Fraction (plain decimal or reduced `numerator/denominator`); integers
are TOML signed integers, checked against the consumer's declared width.

Every TOML root has `schema: int = 1`, `sources: Source[]` and the arrays below.
Source = `{repository: string, revision: string, file: string, lines: string,
symbol: string}`. Paths are repository-relative. Every projected row has `source`.
Lossless XML Node = `{tag: string, attributes: map<string,string>, text: string,
line: int, xml_ordinal: int, children: Node[]}`. Namespace schema attributes are
excluded; comments are not executable nodes. Child order and lexical values are
preserved. `raw: Node` carries all source fields alongside each typed projection;
unknown raw semantics must never be silently treated as executable.

Item fields:

- `template_id:int`, `name:string`, `kind:string` (Weapon/Armor/EtcItem),
  `grade:string`, `bodypart:string`, `bodypart_mask:int`, `weapon_type:string`,
  `armor_type:string`, `etcitem_type:string`, `icon:string`, `handler:string`.
- `weight:int` (source weight units, never grams), `price:int` (Adena),
  `crystal_count:int`, `enchant_enabled:int`, `stackable:bool`,
  `flags:map<string,bool>`, `properties:map<string,string>` (every XML set,
  including those with a normalized projection), `source:Source`, `raw:Node`.
- `soulshots:int`, `spiritshots:int`, `random_damage:int`, `attack_range:int`
  (L2 units; 32 L2 units/tile), `attack_angle:int` (degrees),
  `damage_range:string`, `mp_consume:int`, `reuse_delay:int` (milliseconds),
  `equip_reuse_delay:int` (milliseconds, XML seconds multiplied by 1000),
  `shared_reuse_group:int`, `reduced_soulshot:int[]`, `reduced_mp_consume:int[]`
  (empty or [percent chance, reduced count]), `enchant_hp:bool`.
- `functions:Function[]` in XML order; `skills:SkillRef[]`,
  `enchant4_skills:SkillRef[]`; `conditions:Node[]`.
- Function = `{stat:string, operation:string, order:int, xml_ordinal:int,
  value:string, conditions:Node[], source:Source}`. SET/ENCHANT order 0;
  ADD/SUB order 30; MUL/DIV order 20; ENCHANTHP order 40 unless explicitly
  overridden. An implicit enchant HP flag is separate from literal XML funcs.
- SkillRef = `{id:int, level:int, kind:string, xml_ordinal:int}`; kind preserves
  item/enchant4/set/shield/enchant6/passive/active/trigger context.

## Hash contract

The engine's full Phase4Rules hash uses the accepted design §1.2 typed,
length-delimited encoding, domain `nightfall.phase4.rules.1\0`, plus its Phase3
bundle hash. The generator's `data_sha256` is a reproducibility check, **not a
replacement for that runtime hash**. It hashes UTF-8 canonical JSON (sorted map
keys, compact separators, ensure_ascii=false), preceded by the same domain.
Normalize decimal strings to reduced `n/d` for projected `value`, `chance`,
`bonus_rate`, weight/tax rates and angle bounds. Exclude provenance (`source`,
`sources`, `line`, `lines`) and diagnostic raw XML (`raw`) from semantic hashes;
include all projected properties, conditions, source ordinals, capability
blockers, angle bounds, formula/policy/blacksmith/tax inputs. Keep arrays ordered.
`rules_manifest.toml` lists every other TOML file alphabetically with its semantic
SHA-256; data hash hashes that ordered list and formula_revision. The skill bundle
hash lists committed Phase4 skill definitions by ascending ID and hashes their
parsed semantics. File byte hashes and every source item/file:line are recorded
separately in `source_inventory.json`; committed counts/blocker changes are in
`capability_counts.json`. Neither diagnostic JSON is a runtime hash input.
