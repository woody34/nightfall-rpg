Nightfall · Sequence · Minimal light

From device login to zone admission

01–05: UAuthSubsystem POSTs to {OidcIssuer}/protocol/openid-connect/auth/device with PKCE S256, displays user_code and the verification URL, then polls /protocol/openid-connect/token with the device-code grant. The player authorizes in a browser; polling continues until success or failure.

06–09: After character selection, SessionService.IssuePlayTicket sends the access-token bearer, character_id and a fresh idempotency_key. The response contains ticket, expires_at and ws_url. UNetClientSubsystem upgrades using Authorization: Bearer <ticket>. The API consumes the single-use, 60-second ticket and loads the owned character before HTTP 101.

10–12: Subscribe first; SessionRegistry::admit queues SpawnPlayer or ReplaceSession. Once its tick is applied and durably acknowledged, the session forwards per-player AOI output as protobuf binary frames. Happy path only: character-list RPCs, polling retries, JWKS and repository calls are folded into their actors.

Source: AuthSubsystem.cpp · NetClientSubsystem.cpp · ws.rs · session.rs.
