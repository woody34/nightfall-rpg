Simulation pipeline

The simulation testing pipeline (phase-1a-simulation-testing.md) runs headless Unreal Engine clients against the live server stack inside CI to prove end-to-end functionality, protocol contract coverage, and deterministic zone replay.

Lanes & Triggers: The Push to Main / Nightly lane is the primary blocking gate. It executes on every push to main, scheduled nightly builds, and Gauntlet multi-client soak runs. The PR (Non-blocking) lane runs on pull requests touching apps/client-unreal/**, apps/api/**, or packages/** (or bearing the sim label); it remains advisory and non-blocking until two consecutive flake-free weeks elapse (plan D7, E4.5).

Execution Stack: Runs execute on a persistent self-hosted Linux runner (runs-on: [self-hosted, unreal], plan D7, E4.1) with Unreal Engine 5.8.3, Clang, Docker, and warm Derived Data Cache (DDC) and TurboLink libraries. Each run launches a fresh Docker Compose stack (Postgres, NATS JetStream, Keycloak) and starts apps/api with AUTH_DEV_TOKENS=1, giving bots deterministic test:<uuid> accounts without credential persistence (plan D5).

Bot Runner & Artifacts: run-sim.sh launches N headless processes (-game -nullrhi -nosound -unattended -BotScenario=<path>) driven by UBotScenarioRunner (see bot-runner-lifecycle.html). Runs produce JUnit XML reports (Saved/Sim/<scenario>.xml), UE logs, and recorded binary sessions (.nfr), plus failure diagnostic bundles and optional video capture under Mesa lavapipe on failure (E1.6, E4.6).

Replay-check & Pass/Fail Gate: Every bot recording is replayed by api:replay-check against the server's zone replay log (E3.8, see replay-tool.html). Replay divergence fails the run immediately. The Pass / fail gate strictly enforces: all scenario assertions met within timeouts, 0 unallowed errors or ensures in watched categories (LogNightfall, LogTurboLink, LogNet*), clean process exit, and bit-exact replay (plan D6).

Quarantine & Job Summary: Active flaky scenarios are tracked in a quarantine list with a registered owner and hard expiry date (E4.5); quarantined scenarios execute and record artifacts, but do not trip the PR exit status. The job summary merges contract coverage (E1.7) and transition coverage (E3.9), asserting full traceability for every client-facing feature before phase sign-off (E5.1).
