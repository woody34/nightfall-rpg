Bot runner lifecycle

UBotScenarioRunner is a game-instance subsystem in a -game -nullrhi -nosound -unattended client. Armed happens in Initialize: the scenario path resolves (absolute, launch dir, project dir), the run log <out>/<scenario>.log opens (-BotOutDir, default Saved/Sim), the sentinel hooks GLog and OnEnsureFailed, <scenario>.allow loads, the test-only nf.DropSocket registers, and every parse error is collected (unknown predicate, bad arguments, missing timeout, unknown nf.* command, second nf.Within). Without -DevToken / -DevTokenFile, nf.Login gets a fresh test:<uuid> account.

Running steps: commands run through the console; nf.Expect must hold now; nf.WaitFor polls once per tick and, when it holds, the next step runs on the following tick, or fails at its timeout with the last observed value; nf.Within is enforced on every tick. The first failure ends the run and later assertions are reported as skipped. Not drawn: from Armed, Waiting or Running, an engine shutdown (Deinitialize) aborts the run as failed and still goes to Report.

Report writes <scenario>.xml: one testcase per nf.WaitFor / nf.Expect, plus nf.Within and log and ensure sentinel; a parse failure is one parse scenario testcase. The sentinel runs from Armed to exit; any Error/Fatal line in the watched categories or any ensure not on the allow-list makes the exit code 1 even when every step passed.
