Proxy animation states

Priority order: dead > attack > flinch > locomotion. The animation pose of each entity body is evaluated strictly from timestamped server facts and local render time, without engine world dependencies. Remote proxies render 150 ms behind server time (FSnapshotBuffer::INTERP_DELAY_MS); own pawns evaluate at server time with local movement preview override. Locomotion clip times phase continuously on absolute render time so cycling between Idle, Walk, and Run never restarts the animation timeline.

Attack clips begin wind-up AttackImpactSeconds / AttackPlayRate before the server impact tick, ensuring visual weapon contact coincides exactly with the reported impact. An incoming AttackResult targeting this body triggers a flinch reaction from impact for FlinchSeconds (Cockatrice 0.35 s, Manny 0.20 s; none if art has no flinch take). Active attacks take priority over flinch and cannot be interrupted by incoming damage.

Death preempts all living states at the EntityDied tick. The death clip plays once to completion and freezes on its final frame as Corpse until EntityDespawn or EntityRespawned. Bodies entering the AOI already dead (bCombatant && bDead) skip the death clip directly into Corpse. A respawn or live spawn clears death and purges stale attacks and flinches from prior lives.
