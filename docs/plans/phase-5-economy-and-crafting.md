**B13 Paired Transfer Rule (Owner-Changing Mutations; amends Phase 4 D67/D69 for Phase 5):**
An `ItemInstanceId` NEVER changes when an item changes owner (trade, pickup/drop, warehouse, freight, mail, vendor buy/sell). The ledger records a PAIRED transfer:
- `transfer_out` under the old owner (`after = None` in that owner's view).
- `transfer_in` under the new owner (`before = None` in the new owner's view).
Both rows carry the same mutation receipt/cause and reference each other. D67 freshness is evaluated per owner-view, and the transfer link explicitly exempts the "never seen earlier" rule (the ID's earlier appearance under the prior owner is expected and validated). Canonical fields must be identical across the pair.
Non-character owners hold explicit owner identities in the ledger:
- Ground items: `owner_kind = GroundEntity`, `owner_id = entity_id` (drop: player `transfer_out` -> ground `transfer_in`; pickup: ground `transfer_out` -> player `transfer_in`).
- Warehouse: `owner_kind = WarehouseContainer`, `owner_id = character_id`.
- Freight: `owner_kind = FreightContainer`, `owner_id = account_id`.
- Mail: `owner_kind = MailboxContainer`, `owner_id = message_id`.
- Vendor buy-back: `owner_kind = VendorRefundContainer`, `owner_id = character_id`.

Every in-world economy mutation (including auction bids and manor sow/harvest/turn-in) is a WebSocket intent handled directly by the zone actor while the player is admitted (E14). RPCs are request/response reads (`ListBuylist`, `GetWarehouse`, `GetFreight`, `ListMail`, `ListItemAuctions`, `GetManorData`, `GetRecipeBook`) or out-of-world operations (mail claim/return when not admitted).

- **State digest divergence:** Mutate any canonical field in GroundItemInstance, CorpseState, TradeSession, StoreState, PartyInstance, or AuctionState and confirm digest divergence; rebuild indexes without divergence.
- **Snapshot sizing:** Phase 4 §5.4 exact limits inherited: **1,047,552 / 33,554,432** bytes (enforced C10 limits with exact receipts). Defined worst-case snapshot workload derived from 1k-NPC death-with-drops bench (max drops per death from generated tables x 1,000 + corpses + 8 players x 180 item instances + 32 private stores + 16 active trade sessions + 8 parties; P2-22, E17) fits within the 1,047,552 byte NATS envelope and 33,554,432 byte decoded limit. Pre-run gates: 256 KiB / 1,024 / 8.
- **Performance budgets:**
  - 8-client packaged soak with drops/pickups/vendor traffic maintains tick p99 < 20 ms.
  - Inherited Phase 3/4 budgets: 1,000 NPC mean < 2 ms; 1,000 players/observers mean < 10 ms.
- **Telemetry:** Bounded labels only (op kind, outcome, item class, grade); inherited Phase 4 bounded checks (B12); telemetry correlation to committed export facts; `economy_counters` table rollups populated asynchronously from outbox facts (B8); `infra/scripts/verify-observability.sh` passes.

## 7. Risks

| Risk | Consequence | Mitigation / acceptance |
|---|---|---|
| Ground item buildup per zone | Memory exhaustion or tick budget overrun | Strict 600s item / 60s herb decay (`GC/general.properties:258,262`); worst-case memory bounded by C10 sizing gate (1,047,552 / 33,554,432 bytes). |
| In-memory trade/store intent conflicts | Inconsistent transaction state | Same-tick two-intent ordering rule within single-threaded zone actor (P3-4); all trade validations occur atomically at commit. |
| Economic mudflation (faucets > sinks) | Adena devalued, bot inflation | Bounded adena cap 99.9B; castle tax on purchases; warehouse/freight/mail sinks; recipe material destruction; telemetry monitors faucet/sink ratio via async `economy_counters`. |
| Crafting/trade duplication exploits | Free item generation | All mutations are critical with paired B13 `item_ledger` rows; capacity checks before mutation; two-phase trade commits atomically in single transaction. |
| Replay divergence from drop RNG | Breaks deterministic replay | Per-zone ChaCha12 stream drawn in strict fixed in-tick order in real Phase 3 phases 0–10 with per-callsite draw-order table (E17); 64-bit exact rational rolls (E15); seed and draw cursor recorded in snapshot/digest V7; RNG draw traces exported in schema v2. |
| DB-first bypass of zone authority | Broken determinism and lost updates | Zone actor is single writer for in-world state; DB storage/mail containers mediated strictly via zone critical mutations; RPC mutations freeze DB inputs (E12/E14). |

## 8. Out of scope

- **Phase 6 (World & Content):** Monster spawning runtime, AI aggro tables, broader travel/teleport routes, quests, raid bosses and raid instance dungeons.
- **Phase 7 (Social Systems):** Clan warehouse (200 slots, clan rank access controls), clan halls, castle sieges, Seven Signs competition cycles, Olympiad, and full party extensions (party buffs, command channels, clan integration).

- **Durability, item binding, and Common equipment:** Pinned retail defaults exclude item durability, bind-on-pickup/equip, and un-enchantable Common items.
- **Clan hall / castle tax distribution to lords:** Castle tax is collected into a ledgered sink at the 0% default rate until castles exist in Phase 6/7; distribution to castle lords activates in Phase 7.
