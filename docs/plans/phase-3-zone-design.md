### 1.2 Cast, timers, PvP, geometry and resurrection values

`CastInFlight` stores cast id, caster incarnation, skill id/rank, original command ordinal, start/launch/complete ticks, launch-completed bit, sampled affect limit and selected/launch-filtered target bindings, original animation milliseconds, independent damage-interrupt deadline, start-time effective timing/cost inputs, and `TargetBinding { entity, incarnation }` where applicable. Include start position only for rules that actually use it. SINGLE binds one target; RANGE binds its center target; POINT_BLANK binds the caster. Never silently change an accepted cast's target when selection changes. Revalidate current existence/incarnation, life, range, protection, peace and status at completion. Damage/effect strength uses current effective stats at completion; timing does not stretch when haste expires. Periodic DIFF strength is frozen; PER reads the current resource at each pulse (§1.3).

Execution deadlines are absolute `Tick(u64)` (periodic ideal-ms phase is additional canonical data, §1.3) and half-open: active while `now < until`, due when `until <= now`. Use checked arithmetic and `ceil_ms_to_ticks` after source millisecond truncation; cast completion is at least start+1. `TICK_MS=100` and `Tick` exist (`Z/entity.rs:15`, `:23`). Reuse is keyed by skill id across ranks and starts on accepted cast start, never completion; cancellation refunds neither reuse nor MP1 (`G/model/actor/L2Character.java:1514`, `:1533`, `:1542`). §6 pins static/magic/physical reuse and cast-time branches. F3/F4 supersede D-R2’s completion-based cutoff: let A be the nonnegative `calcCastTime` animation in source milliseconds, m=trunc(A). For A>0, launch delay L=max(0,trunc(A−(continuous?300:0))−400); impact delay I=L+(m==0?0:400). For A=0, L=I=0. Convert each nonnegative absolute offset once: launch_at=start+ceil(L/100), complete_at=start+max(1,ceil(I/100)); zero-delay launch occurs within accepted start, without recursive impact. Store interrupt_until=start+max(0,floor(m/100)−2), with an empty window when the signed offset is <=0. The max merely encodes an already-empty interval without u64 underflow. Window is `start <= t < interrupt_until`, independent of continuous head start and tick-ceiled impact. Sources: `G/model/actor/L2Character.java:1495`, `:1508`, `:1614`, `:1625`, `:1643`, `:1645`, `:4577`; source scheduler forwards nonpositive delays (`G/ThreadPoolManager.java:132`). `hitCancelTime` stays imported but unused. `coolTime` is likewise parsed but has no getter caller in the pinned game; finalization is immediate after effect execution, so no invented post-cast recovery lock (`G/model/skills/Skill.java:633`; `G/model/actor/L2Character.java:4666`, `:4690`). Only the scalar fields persist; derived color does not. `RegenSchedule { next_tick: Tick }` uses 30-tick periods, initialized to spawn/admission/resurrection tick + 30, then advanced by 30. Restored replay preserves the exact original deadline; fresh admission starts a new schedule. ### 1.3 EffectList and ordering

`EffectList` contains `BTreeMap<EffectId, ActiveEffect>` as canonical state. Derived indexes are `BTreeMap<StackKey, EffectId>` and `BTreeSet<(Pool, applied_tick, EffectId)>`; rebuild and validate them from canonical entries after restore. An `ActiveEffect` stores skill/rank, source id/incarnation/source kind, original target incarnation, applied/expiry ticks (optional expiry for explicit permanent effects), pool, abnormal type/level, ordered handler instances and their next ideal pulse millisecond offset, pulse index and typed DIFF/PER payload fields. Store skill-wide effects as one entry occupying one slot; `Buff { mul pDef, add evasion }` is not two buffs. Multiple periodic handlers retain their source XML ordinal.

`Pool = Buff | SongDance | Debuff | System`; System is only for data-confirmed slot-exempt effects such as reconstructed passives/death penalty. Normal capacities are 20+clamped Enlarge contribution (0..4), 12, 8. Passives live in learned-skill-derived modifier sources, not in finite timed pools. Model death penalty as a system modifier source for skill 5076 at scalar rank, with stay-after-death semantics and no expiration; do not duplicate its scalar as a separately restored, independently ranked buff.

Stack key is `Abnormal(abnormal_type)` except NONE, which is `Skill(skill_id)`. For an existing stack, lower abnormal level is ignored without expiry restart or eviction. Equal/higher replaces the whole old application, emits removal before application, restarts duration/pulse schedule and receives a fresh EffectId. Source identity is not part of the stack key. On no conflicting stack, enforce capacity, removing oldest `(applied_tick, EffectId)` first. Slot-cap shrink immediately evicts the oldest excess buffs in that same order. Honor supported irreplaceability/category flags in dispels; if a protected-slot overflow case cannot be represented faithfully, mark that skill deferred or decide it explicitly, never loop forever looking for an eviction candidate.

All expiry removals for a tick are ordered `(expires_at, target_entity_ordinal, target_id, effect_id)`. Pulses are ordered `(due_tick, target_entity_ordinal, target_id, effect_id, handler_ordinal)`. Container admission validates replacement/reserves the slot, removes the old entry and starts the new handlers in source scope/XML order. For each continuous handler: run onStart, register its pulse schedule, then install its generic Funcs (`G/model/skills/BuffInfo.java:260`, `:266`, `:272`, `:278`). Rebuild before each subsequent stat read; do not preinstall all modifiers before hooks. Hook-owned Funcs have distinct ownership and install exactly once; handler-local function ordinals put them before that handler’s generic Funcs at equal priority. Instant handlers execute while building BuffInfo, before continuous-container installation (§6); their successful effects survive a later stack rejection. The instant part of A2 can succeed even if its continuous part is resisted or rejected by stronger stacking; result entries distinguish the two. Duration expiry at t precludes a pulse at t.

`StatusFlags` is a typed integer mask derived from all live effects: stun, sleep, root, magic mute, physical mute, paralyze, and data-supported resurrection/debuff blocks. Never clear a flag by blindly removing one effect; another effect may still provide it. Stun/sleep/paralyze stop movement, cancel in-flight cast and swing, and suppress new attacks/casts; root stops movement/chase but permits in-range actions; magic/physical mute cancels or rejects only matching casts. Damage-breakable removal uses skill flags and `awake`, not a universal sleep rule: player status calls it for all non-HP-consumption damage, including DoT; generic/NPC status calls it only for non-DoT/non-HP-consumption damage. Non-toggle TickHp supplies awake=true (`G/model/actor/L2Character.java:5220`; `G/model/CharEffectList.java:847`, `:872`). After that removal, if still stunned and damage is neither DoT nor HP consumption, draw `Rnd.get(10)` and remove stun only on zero, before CP/HP subtraction (`G/model/actor/status/PcStatus.java:82`, `:93`, `:185`; `G/model/actor/status/CharStatus.java:142`, `:149`). These status hooks are not gated on positive absorbed damage: a valid zero-valued reduceHp call still reaches them. Paralyze has no analogous stun roll; only its own removal flags/lifecycle apply. Hard disable cancellation does not use the damage-interrupt window or a random roll. `TargetMe` remains deferred; GetAgro enqueues forced intention without changing hate, while AddHate changes hate (§3). Keep `HateLedger::most_hated` unchanged (`Z/combat.rs:344`).

**Periodic contract (F5/F6).** XML `ticks` is an interval factor, never a pulse count. I_ms=ticks×666, with positive bounded ticks and checked multiplication; 666 is pinned at `game/src/main/resources/config/character.properties:145`. First pulse is application+ceil(I_ms/100); subsequent pulse n is application+ceil(n×I_ms/100), not previous rounded tick+ceil(I_ms/100). Persist ideal next-pulse milliseconds/pulse index as well as its derived tick, retaining sub-tick phase across snapshots and paused admission (store remaining ideal milliseconds relative to checkpoint tick). Advance even suppressed peace-zone pulses. Expiry wins at equal due tick; no pulse at/after expiry, no wall-time catch-up. For ticks=1 the first three offsets are 7,14,20 ticks; ticks=3 gives 20,40,60. Source schedules first and repeated work at I_ms (`G/model/skills/BuffInfo.java:269`); for non-toggle skills the handler’s false return does not end the effect (`:295`, `:303`).

Amount multiplier M is Java binary32 `float(I_ms)/1000f` widened to double, not integer division or the rounded schedule interval (`G/model/effects/AbstractEffect.java:148`). Generate its exact binary rational with the integer-only binary32 adapter (§6.2), retaining precision through multiplication. DIFF freezes the coefficient inputs for power×M; PER stores power and the immutable multiplier reference and reads current HP/MP (whole+restoration fraction) each pulse: current×power×M, **no /100** (`E/ticks/TickHp.java:61`, `:64`, `:68`; `E/ticks/TickMp.java:53`, `:56`, `:60`). Negative TickHp magnitude is capped at currentHP−1 before whole-damage conversion and before player-sourced CP absorption (`E/ticks/TickHp.java:73`, `:79`): HP10/CP20 and computed damage50 → capped9 → CP11/HP10; HP1 → damage0, even with CP remaining. Thus it never kills; TickHpFatal is deferred. Positive TickHp/MP uses recoverable maxima, preserving already-above-cap resources via the source early exit; negative TickMp drains MP to zero (`E/ticks/TickHp.java:82`, `E/ticks/TickMp.java:65`; `G/model/actor/status/CharStatus.java:166`). Restoration retains Q fractions; drains use whole truncation, consistent with D-R12.

Death removes all non-stay-after-death effects in EffectId order, cancels cast/swing, invalidates offers and fractional resources, then applies any new death penalty rank. Class transfer filters effects by stay-on-subclass-change before new effective stats and resource ratios. Despawn invalidates target bindings; effects on other entities may retain frozen source attribution without retaining a pointer to a departed entity. A departed/dead source receives no new live kill credit, matching the existing living-killer rule (`Z/state_combat.rs:637`).

### 6.2 Sqrt/rounding oracle contract

Proposed runtime sqrt policy: for a nonnegative Q value x, `sqrt_q(x)=isqrt(x*Q)` is a **lower bound**, not automatically an approved whole-damage result. Retain the upper bound `(sqrt_q+1)/Q` through the rest of the positive rational pipeline. If both endpoints produce the same final integer, that integer is proven; if they straddle an integer or chance comparison boundary, refine using checked i128 interval arithmetic or a cross-multiplied squared comparison with factors canceled before multiplication. No unchecked large products. For admitted bounded stats, choose/prove a maximum refinement precision at load time; if it cannot prove a result, fail registry validation, not a live spell with an arbitrary guess. Store only Q state; wider precision is local math. A12 permits a single Q-sqrt only after independent oracle agreement on required vectors; that is not exhaustive equivalence.

E1’s independent Fraction/Decimal oracle brackets irrational roots with integer inequalities over pinned literals; a pinned Java harness may supplement **future** verification. Oracle artifacts must contain source revision/path/line, inputs, explicit injected rolls, intermediate exact quantities, every rounding site, expected whole outputs/branch outcome and vector-set hash. Rust cannot generate its own expected values. Golden vectors cover every executable skill/rank, class/level boundaries, buffs in both application orders, max caps, negative add/sub, perfect/nonperfect squares, near-integer damage/near-half rounding, PvE/PvP crit, both failure rolls and >=10 level-gap branch.
