- B2 (plan Q2, private stores) Pinned OfflineTradeEnable=False governs: private stores are zone state only and CLOSE on disconnect, departure or server restart (no persistent private_stores table; A15 amended); the client shows the store as closed on re-admission; no notification invented beyond what the pinned client receives.
- B3 (plan Q3, trade cancellation) No invented 150-unit / 120 s rules: trade sessions follow pinned semantics only — cancellation when a partner departs the zone, dies, or moves beyond the pinned trade interaction radius (cite the exact pinned check in RequestTradeRequest/TradeList), TransactionInterval flood protection as pinned; the 05 §5 numbers are removed from the plan and recorded as rejected research.
- B4 (plan Q4, item auction) Item auction is implemented as the pinned ItemAuctionManager state machine (periods, bidding with adena movement as zone critical mutations, finalization awarding the item via the item path) driven by a fixture schedule; "fixture-only inputs" means the auctioned items and schedule come from fixtures, not that bidding is read-only.
- B5 (design Q1, ground item identity) A GroundItem is a zone ENTITY (EntityId in the existing entity id space, with incarnation, for spawn/AOI/pickup targeting) that CARRIES an ItemInstanceId (D8 allocator) for the item it holds; the ledger `drop`/`pickup` rows use the ItemInstanceId; the wire GroundItem spawn detail carries both. No separate GroundItemId type.
- B6 (design Q2, refund tab) Pinned: the refund buffer clears on logout (L2PcInstance.java:2539-2543) — the 12-item refund tab is zone state only, cleared on departure, not persisted in Phase5Checkpoint; items in it are destroyed per pinned semantics (document the pinned destruction).
- B7 (design Q3, trade abort) A disconnect/departure during a locked-but-unconfirmed trade cancels the session for both parties exactly as pinned (TradeList cancel; items return to owners' inventories; no penalty, no partial transfer); the remaining party receives the pinned cancel notification; no adena/fee invented.
- B8 (design Q4, economy counters) economy_counters rollups are populated ASYNCHRONOUSLY by the outbox relay/consumer from the item/economy outbox facts (never inside the checkpoint transaction); they are observability data for Phase 9, idempotent on re-delivery (fact id dedupe).
