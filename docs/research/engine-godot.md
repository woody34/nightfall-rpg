# Engine research: Godot Engine (4.x)

- **Engine version that we evaluated:** Godot 4.7.2 stable (released 2026-08-18). 4.8 is in dev snapshots (dev 5 on 2026-09-10, feature freeze expected late September 2026)
- **Research date:** 2026-10-07
- **Context:** Nightfall (an MMORPG that Lineage 2 inspired). The Rust server is authoritative (axum + tonic + NATS). The client uses gRPC-web for request/response, and a WebSocket with protobuf frames for real-time data. Native desktop is necessary. Browser deployment is desirable.
- **Status legend:** Native / Plugin / Partial / Missing. Maturity: stable / beta / experimental / abandoned.

## Narrative

**Where Godot is in October 2026.** Godot 4.7.2 is the current stable release (18 Aug 2026), and 4.8 is some weeks from feature freeze. The engine releases a new minor version approximately each six months. The last three releases were unusually important to a 3D MMO client:

- 4.4 made Jolt a built-in physics engine and made Metal the default on Apple Silicon.
- 4.6 made Jolt the default, and it made Direct3D 12 the default on Windows (because "Vulkan is unfortunately unstable on Windows"). It also rewrote SSR, added a full IK framework (`IKModifier3D` with FABRIK/CCDIK/TwoBone/Spline/Jacobian solvers), and added delta-encoded patch PCKs.
- 4.7 added HDR output, AreaLight3D, wasm64 web exports and the Asset Store.

4.8 adds mip-level texture streaming, which directly decreases the VRAM pressure in large 3D worlds. The licence is MIT with no royalties. The only cost would be a W4 Consoles subscription, if consoles become important. The funds are better than at all other times in the history of the project. The Development Fund is "very healthy and consistent", and the community "has doubled in size in the last couple of years". W4 Games (which the creators of Godot started) closed an $18M Series B led by Tencent on 25 Aug 2026. This gives funds for console ports, W4 Cloud and upstream renderer work.

**Strengths for Nightfall.** The character and gameplay layer is complete. It has PBR, GPU skinning, AnimationTree state machines and blend spaces, root motion, and retargeting at import time through SkeletonProfileHumanoid. It now also has a correct IK stack. Jolt gives a fast, stable character controller and raycasts. NavigationServer3D gives navmesh baking (editor and runtime), agents and RVO avoidance for click-to-move and mob paths. The UI system uses Control nodes, with RichTextLabel, drag-and-drop, Tree/ItemList and full localization (CSV/PO, plurals, RTL, live preview). It is better than all that a Phaser prototype gives, and Godot uses it to build the editor. The high-level multiplayer API is optional, and this is very important for a custom authoritative server. `WebSocketPeer`, `StreamPeerTCP`, `HTTPClient` and `PacketPeerUDP` are first-class, and the docs explicitly expect "a custom server implementation on the backend". Nothing works against you. The editor is small and native on Linux, you can script it headless for CI, and the iteration for GDScript is instant.

**The Rust path through gdext.** This decision makes Godot attractive, not only acceptable. godot-rust/gdext (`godot` 0.5.5, Aug 2026) maps "the vast majority of Godot APIs" to Rust and supports Godot 4.2-4.6+. It tests hot reload in CI. Since 0.5, it can depend on other gdext crates as rlibs, and it has prebuilt Wasm bindings. The practical architecture is one cdylib crate with these properties:

- It depends on the current `nightfall-domain` crate (messages that prost generates, entity state, movement and interpolation math).
- It is responsible for the WebSocket and gRPC-web clients (tonic/`tonic-web-wasm-client` or the `WebSocketPeer` of Godot).
- It gives some `#[derive(GodotClass)]` nodes and signals, and the GDScript scenes bind the UI to them.

The protobuf decoding, the snapshot buffers and the prediction stay in Rust. They are literally the same code that the server runs. The alternative with GDScript only (godobuf, a pure-GDScript protoc) is satisfactory for messages at a low rate, but not for entity frames at 20 Hz. Cautions:
- gdext is 0.x and it says so ("expect occasional breaking changes", with migration guides).
- Rust panics abort the extension.
- Hot reload operates only in the editor.
- You debug with LLDB against the Godot binary, with symbols only for Rust.

**Weaknesses.** The documented weak area of Godot is exactly the open-world dimension of an MMO:

- There is no world partition, HLOD or impostor system in core.
- Occlusion is a CPU Embree rasterizer with static baked occluders.
- Terrain is the third-party Terrain3D GDExtension (good, MIT, 1.0.x), not engine code.
- The scene tree becomes a bottleneck at tens of thousands of nodes. Thus, ambitious projects control RenderingServer/PhysicsServer directly (a July 2026 forum thread tells of exactly this for a city with 100k nodes).
- SDFGI operates with a 4-hour day cycle, but it is only for Forward+ and it is heavy. The promised HDDAGI replacement is not released three years after its announcement.
- Crowd rendering uses one draw for each character, with no built-in vertex-animation-texture path.

The web is the other weakness. The web export is WebGL2 Compatibility only (no WebGPU, no Forward+). C# cannot export to web. The gdext book says that the Rust extension on web is "experimental". It needs nightly Rust, emscripten 3.1.74 and separate threads/no-threads builds. Also, there is no LTS. Each minor release has support only until the first patch of the next release. Thus, a project of many years will upgrade two times each year.

**Fit.** Lineage 2 used zones (hunting grounds, towns, teleporters), and that model is good for Godot. Do these steps:
- Release zones as PCKs/scenes that load separately, with Terrain3D regions.
- Use automatic mesh LOD and visibility ranges.
- Bake the occluders for each zone.
- Keep the node count for each entity in the client small (one scene for each visible player/mob, pooled).

If we accept that constraint, Godot covers approximately 25 of the 32 rows natively. Nightfall already has the two largest gaps (network layer and shared simulation) in Rust. The main risks are:
- Scale: prove 300 animated characters and a zone load/unload cycle in the first month.
- The web export: make it a stretch goal. The fallback is a desktop-first client with a lightweight web viewer that uses GDScript only.
- API churn across Godot minor releases and gdext 0.x releases: pin the two for each milestone.

No comparable MMO was released on Godot, thus Nightfall would go into new areas. But the funds, release speed and Rust integration of the engine are all much better than two years ago.
