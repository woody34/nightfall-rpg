# Engine research: Godot Engine (4.x)

- **Engine version evaluated:** Godot 4.7.2 stable (released 2026-08-18); 4.8 in dev snapshots (dev 5 on 2026-09-10, feature freeze expected late September 2026)
- **Research date:** 2026-10-07
- **Context:** Nightfall (Lineage 2-inspired MMORPG). Authoritative Rust server (axum + tonic + NATS). Client speaks gRPC-web for request/response and a WebSocket carrying protobuf frames for real-time. Native desktop required; browser deployment desirable.
- **Status legend:** Native / Plugin / Partial / Missing. Maturity: stable / beta / experimental / abandoned.

## Narrative

**Where Godot stands in October 2026.** Godot 4.7.2 is the current stable (18 Aug 2026), 4.8 is weeks from feature freeze, and the engine ships a new minor roughly every six months. The last three releases were unusually relevant to a 3D MMO client: 4.4 made Jolt a built-in physics engine and Metal the default on Apple Silicon; 4.6 made Jolt the default, made Direct3D 12 the default on Windows (because "Vulkan is unfortunately unstable on Windows"), rewrote SSR, shipped a full IK framework (`IKModifier3D` with FABRIK/CCDIK/TwoBone/Spline/Jacobian solvers) and added delta-encoded patch PCKs; 4.7 added HDR output, AreaLight3D, wasm64 web exports and the Asset Store. 4.8 brings mip-level texture streaming, which directly attacks VRAM pressure in large 3D worlds. Licensing is MIT with no royalties; the only money that would change hands is a W4 Consoles subscription if consoles ever matter. Funding looks healthier than at any point in the project's history: the Development Fund is described as "very healthy and consistent", the community "has doubled in size in the last couple of years", and W4 Games (founded by Godot's creators) closed an $18M Series B led by Tencent on 25 Aug 2026, which keeps console ports, W4 Cloud and upstream renderer work funded.

**Strengths for Nightfall.** The character and gameplay layer is genuinely complete: PBR, GPU skinning, AnimationTree state machines and blend spaces, root motion, import-time retargeting through SkeletonProfileHumanoid, and now a proper IK stack. Jolt gives a fast, stable character controller and raycasts; NavigationServer3D provides navmesh baking (editor and runtime), agents and RVO avoidance for click-to-move and mob pathing. The Control-based UI system with RichTextLabel, drag-and-drop, Tree/ItemList and full localization (CSV/PO, plurals, RTL, live preview) is better than anything a Phaser prototype offers and is what the editor itself is built from. Crucially for a custom authoritative server, the high-level multiplayer API is optional: `WebSocketPeer`, `StreamPeerTCP`, `HTTPClient` and `PacketPeerUDP` are first-class and the docs explicitly expect "a custom server implementation on the backend". Nothing fights you. The editor is small, Linux-native, scriptable headless for CI, and iteration for GDScript is instant.

**The Rust-via-gdext path.** This is the decision that makes Godot attractive rather than merely acceptable. godot-rust/gdext (`godot` 0.5.5, Aug 2026) maps "the vast majority of Godot APIs" to Rust, supports Godot 4.2-4.6+, tests hot reload in CI, and since 0.5 can depend on other gdext crates as rlibs and ships prebuilt Wasm bindings. The practical architecture is a single cdylib crate that depends on the existing `nightfall-domain` crate (prost-generated messages, entity state, movement and interpolation math), owns the WebSocket and gRPC-web clients (tonic/`tonic-web-wasm-client` or Godot's own `WebSocketPeer`), and exposes a few `#[derive(GodotClass)]` nodes plus signals that GDScript scenes bind UI to. Protobuf decoding, snapshot buffering and prediction stay in Rust and are literally the same code the server runs; the GDScript-only alternative (godobuf, a pure-GDScript protoc) is fine for low-rate messages but not for 20 Hz entity frames. Caveats: gdext is 0.x and says so ("expect occasional breaking changes", with migration guides); Rust panics abort the extension; hot reload is editor-only; and debugging is LLDB against the Godot binary with Rust-only symbols.

**Weaknesses.** Godot's documented weak spot is exactly the open-world dimension of an MMO. There is no world partition, HLOD or impostor system in core; occlusion is a CPU Embree rasterizer with static baked occluders; terrain is the third-party Terrain3D GDExtension (good, MIT, 1.0.x) rather than engine code; and the scene tree becomes a bottleneck at tens of thousands of nodes, which pushes ambitious projects toward driving RenderingServer/PhysicsServer directly (a July 2026 forum thread describes exactly this for a 100k-node city). SDFGI handles a 4-hour day cycle but is Forward+-only and heavy; the promised HDDAGI replacement has not shipped three years after its announcement. Crowd rendering is per-character draws with no built-in vertex-animation-texture path. The web story is the other weakness: web export is WebGL2 Compatibility only (no WebGPU, no Forward+), C# cannot export to web at all, and the Rust extension on web is "experimental" by the gdext book's own words, requiring nightly Rust, emscripten 3.1.74 and separate threads/no-threads builds. And there is no LTS: each minor is supported only until its successor's first patch, so a multi-year project will be upgrading twice a year.

**Fit.** Lineage 2 itself was zone-based (hunting grounds, towns, teleporters), and that model suits Godot: ship zones as separately loaded PCKs/scenes with Terrain3D regions, use automatic mesh LOD plus visibility ranges, bake occluders per zone, and keep the client's per-entity node count modest (one scene per visible player/mob, pooled). With that constraint accepted, Godot covers roughly 25 of the 32 rows natively, and the two biggest gaps (network layer and shared simulation) are things Nightfall already owns in Rust. The main risks are scale (prove 300 animated characters and a zone-load/unload cycle in the first month), the web export (treat as a stretch goal; a desktop-first client with a GDScript-only lightweight web viewer is the fallback), and API churn across Godot minors and gdext 0.x releases (pin both per milestone). No comparable MMO has shipped on Godot, so Nightfall would be charting new ground, but it would be doing so on an engine whose funding, release velocity and Rust integration story are all materially better than they were two years ago.
